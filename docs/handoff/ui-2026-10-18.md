## Endpoint shapes

### Categories (new, no flag, no auth)

```
GET /api/categories
→ { "categories": [ { "id": "ring", "label": "Ring", "family": "jewelry", "sizeRule": "ring", "attributeKeys": ["color","cut","details"] }, … ] }
```

- **`id` values:** `jacket`, `top`, `pants`, `bag`, `watch`, `necklace`, `bracelet`, `ring`, `earrings`, `other`.
- **`sizeRule`:** `clothing`, which applies to the apparel categories and to `bag` (unchanged behavior), `ring` or `none`.

### Garments and preferences

- **Manual crop:** `POST /api/sessions/{id}/garments` with `{ frameAssetId, box01, category, description? }`. `category` now also accepts `watch`, `necklace`, `bracelet`, `ring` and `earrings`.
- **Ring size:** `PATCH /api/sessions/{id}` with `{ expectedRevision, preferences: { ringSize: { raw: "7" } } }`. The value is stored as `{ raw: "7", system: "us" }`. Anything outside US 3–15 (halves and quarters allowed) returns **422**. Clothing `preferences.size` never produces a `size` check for watches or jewelry. Rings get a `"ring size"` constraint check.
- **Accessory results:** they're always `identityTier: "similar"`. They may carry the warning *"Metal, stones and authenticity are the seller's description; ClipCart doesn't verify them."*
- **Accessory observations:** `observedAttributes` may include `"appearanceNormalized": ["true"]`. Show `visibleText` as "Text seen on the item", never as a brand.

### Research (`FEATURE_AGENT_RESEARCH`; `RESEARCH_PROVIDER` = `fixture` | `solescout` | `manual`)

```
POST /api/sessions/{id}/research-jobs   { idempotencyKey? }  → { job: ResearchJob }   (status "pending")
GET  /api/research-jobs/{jobId}                               → { job: ResearchJob }
POST /api/research-jobs/{jobId}/import  { products: SubmittedProduct[≤20], notes? } → { job }   (owner-only; manual import)
     404 not_found | 409 already_completed | 422 invalid_import (the job stays as it was)
```

`ResearchJob` adds `styleHints`, `resultSource` (`provider` | `manual_import`), `mode` `manual` and `provider` values `solescout` and `manual`. A failed catalog fallback ends with `error.code: "catalog_unavailable"` and `retryable: true`.

`ResearchProduct` adds:

- **Labelling:** `source` (`agent` | `catalog` | `manual_import`, set by the server).
- **Listing details:** `imageUrl`, `brand` with `brandBasis` (`page_text` | `catalog_record`), `condition` and `sellerKind`.
- **Availability and evidence:** `variants[]`, with `availability` `available` | `unavailable` | `unknown`. Unavailable variants are **kept**. Also `evidence[]`.
- **Comparison:** `offerGroup` = `{ id, equivalence: "identifier_match"|"approximate"|"single", basis, offerCount, lowestConfirmedPrice, isLowestConfirmed, uncertainPriceCount }`.

### Style memory (`FEATURE_STYLE_MEMORY`)

- **Memories:** `POST /api/style/memories` with `{ kind, value, source }`.
  - **New kinds:** `tone_like` / `tone_avoid` (`gold-tone`, `silver-tone`, `rose-gold-tone`, `black`, `two-tone`), `ring_size` (`{ raw }`) and `style_like` / `style_avoid` (`vintage`, `minimalist`, `streetwear`, `workwear`, `preppy`, `athleisure`, `y2k`, `outdoor`, `techwear`, `western`, `bohemian`, `classic`, `grunge`, `punk`).
  - **Sources clients may send:** `preferences_form`, `style_panel`, `style_note` and `chat_refinement`.
- **`StyleMemory` additions:** `confidence` (1.0 stated; inferred ≤0.9; model ≤0.7), `lastEvidenceAt`, `evidence[] {eventId, type, at, excerpt}` and a new `source: "model_interpretation"`.
- **Profile:** `GET /api/style/profile` → `profile` (`StyleProfileView`) adds `tonesLike`, `tonesAvoid`, `ringSize`, `stylesLike` and `stylesAvoid`. Entries add `confidence` and `source`. `styleModel` is a `StyleModelInfo`.
- **Events:** `StyleEvent.item` adds `condition` and `styleFacts[] {tag, field, excerpt}`.
- **Interpretations:**
  - `GET /api/style/interpretations` → `{ status, pendingEvents, notBefore, runs[], rankingInfluence, styleModel }`.
  - `POST /api/style/interpretations/run` runs any queued interpretation now.
  - With no model configured, `status` is `waiting_for_model` when events are pending.

## UI work (Claude app owns all of it)

1. **Categories and sizes:**
   - Build pickers (manual crop, garment edit) from `GET /api/categories`.
   - Hide clothing size when `sizeRule` is `none`.
   - Show a "Ring size (US)" input when it's `ring`.
   - Offer tone chips for watches and jewelry.
2. **Accessory results:** show the "Similar look" tier, the seller-claims warning and "Text seen on the item".
3. **Research:**
   - Label the source as "From SoleScout's store record", "Found by research agent" or "Imported manually".
   - Show offer groups with "Lowest confirmed price" (never on a null price), and "Looks like the same product — not confirmed" for `approximate`.
   - Show unavailable variants as labelled, not hidden, and the brand basis.
   - Set `referrerpolicy="no-referrer"` on images.
   - Add a labelled manual-import form for `manual`, failed or expired jobs.
4. **Style panel:**
   - Editable style and tone chips, and a ring-size field.
   - Confidence (High ≥0.7, Medium ≥0.45, Low) with evidence excerpts and dates.
   - Label model memories "Suggested by the style model from your saves (doesn't affect ranking)" while `rankingInfluence` is false.
   - Wardrobe groups: "Owned (you said)", "Owned (verified)", "Saved (interest)", "Hidden" and "Opened links (not purchases)".
   - `StylePanel.tsx` currently has **type-compatible labels only** for the new kinds.
5. **Browser captures:** show "Browser capture · {sourceTitle or host}". This is already done in `App.tsx`. Keep it.
